# 9.11 Important Boundary Rule

We now have three levels:

```text
PAGE
 ↓
FEATURE COMPONENT
 ↓
SHARED UI
```

Example:

```text
ProjectDetails
      ↓
ProjectTaskList
      ↓
TaskItem
      ↓
Button / Badge
```

This gives us a practical component architecture without exploding the project into hundreds of files.

# STEP 10 — DATA MODEL

Now we need to decide **what information DevFlow actually works with**.

This is important before coding because our UI shouldn't be built around random fake objects.

We'll start with four core entities:

```text
User
Project
Task
Activity
```

### User

```js
{
  id,
  name,
  email,
  avatar
}
```

### Project

```js
{
  id,
  name,
  description,
  status,
  progress,
  createdAt
}
```

### Task

```js
{
  id,
  projectId,
  title,
  description,
  status,
  priority,
  dueDate,
  createdAt
}
```

### Activity

```js
{
  id,
  projectId,
  taskId,
  type,
  message,
  createdAt
}
```

The relationships matter:

```text
Project
   │
   └── projectId
          ↑
         Task

Project
   │
   └── projectId
          ↑
       Activity
```

This prepares us for the API/database thinking you'll encounter later in Phase 3.

# STEP 11 — STATE STRATEGY

We'll keep state simple initially.

### Local UI state

Things such as:

```text
Modal open/closed
Search input
Selected filter
Form fields
Dropdown open/closed
```

→ local component state.

### Feature/application data

Things such as:

```text
Projects
Tasks
Activities
```

→ centralized enough that multiple components can consume/update them cleanly.

For MVP, we'll start with a **frontend data layer + React state**, rather than adding Zustand.

If the project genuinely outgrows that approach, we'll evaluate it then.

# STEP 13 — MVP SCOPE

We need to control scope.

### MUST HAVE

```text
Landing
Dashboard
Projects
Project Details
Tasks
Task CRUD interactions
Search/filter
Responsive navigation
Loading/error/empty states
Activity
Basic analytics
Profile
Settings
Routing
```

### SHOULD HAVE

```text
Good empty states
Form validation
Responsive transformations
Accessible interactions
Persistent local data
Polished UX
```

### NOT NOW

```text
Authentication backend
Real database
Real-time collaboration
Socket.io
AI assistant
Advanced analytics
Complex permissions
Team management
```

Those belong to future iterations.
