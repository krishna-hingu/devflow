# STEP 7 — RESPONSIVE STRATEGY

Step 6 is complete. ✅

## 7.1 Our Three Layout Targets

We'll design for:

```text
Desktop
≥ 1024px

Tablet
768px – 1023px

Mobile
< 768px
```

These aren't rigid rules for every component. They're our initial layout strategy.

---

# 7.2 Desktop

Desktop is the primary workspace experience.

Conceptually:

```text
┌──────────────┬────────────────────────────────────┐
│              │ Header                             │
│              ├────────────────────────────────────┤
│   Sidebar    │                                    │
│              │                                    │
│ Dashboard    │          Main Content              │
│ Projects     │                                    │
│ Activity     │                                    │
│ Analytics    │                                    │
│              │                                    │
│──────────────│                                    │
│ Profile      │                                    │
│ Settings     │                                    │
└──────────────┴────────────────────────────────────┘
```

### Desktop behavior

Sidebar:

* Visible
* Persistent
* Full navigation available

Main content:

* Flexible width
* Maximum content width where appropriate
* Comfortable spacing

For data-heavy screens such as Projects and Analytics, we can use the available horizontal space rather than unnecessarily constraining everything.

---

# 7.3 Tablet

Tablet has less horizontal space, so the navigation becomes less dominant.

Conceptually:

```text
┌──────────┬──────────────────────────────────────┐
│          │ Header                               │
│ Sidebar  ├──────────────────────────────────────┤
│          │                                      │
│ Icons /  │           Main Content               │
│ compact  │                                      │
│ nav      │                                      │
│          │                                      │
└──────────┴──────────────────────────────────────┘
```

The exact behavior can be:

```text
Desktop sidebar
      ↓
Compact sidebar
```

Instead of immediately removing navigation.

This gives us an opportunity to practice responsive layout without creating an entirely different application.

---

# 7.4 Mobile

Mobile is a different interaction environment.

We should not try to squeeze the desktop dashboard into a 375px screen.

Instead:

```text
┌─────────────────────────────┐
│ ☰   DevFlow          User  │
├─────────────────────────────┤
│                             │
│ Dashboard                   │
│                             │
│ Summary                     │
│ ┌──────────┐ ┌──────────┐  │
│ │ Projects │ │ Tasks    │  │
│ └──────────┘ └──────────┘  │
│                             │
│ Current Work                │
│ ┌─────────────────────────┐ │
│ │ Project                 │ │
│ │ Progress                │ │
│ └─────────────────────────┘ │
│                             │
└─────────────────────────────┘
```

### Mobile principles

* Full-width content
* Compact header
* Navigation accessible through a mobile menu
* Cards stack vertically
* Multi-column grids collapse
* Tables transform when necessary
* Forms become single-column
* Touch targets remain comfortable

---

# 7.5 Dashboard Transformation

Desktop:

```text
┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│Projects│ │ Tasks  │ │Complete│ │Progress│
└────────┘ └────────┘ └────────┘ └────────┘
```

Tablet:

```text
┌────────┐ ┌────────┐
│Projects│ │ Tasks  │
└────────┘ └────────┘

┌────────┐ ┌────────┐
│Complete│ │Progress│
└────────┘ └────────┘
```

Mobile:

```text
┌──────────────────┐
│ Projects         │
└──────────────────┘

┌──────────────────┐
│ Open Tasks       │
└──────────────────┘

┌──────────────────┐
│ Completed        │
└──────────────────┘
```

The **information stays the same**.

The **layout changes**.

That's an important responsive principle.

# 7.7 Tasks

Desktop can use a table/list:

```text
Task          Priority    Status       Due
────────────────────────────────────────────
Build API     High        Progress     Today
Navbar        Medium      Pending      Tomorrow
```

Mobile should not become:

```text
Task | Priority | Status | Due
      ↓
[everything squeezed together]
```

Instead, we can transform each task into a compact item/card:

```text
┌────────────────────────────┐
│ Build API                  │
│ High · In Progress         │
│ Due today                  │
└────────────────────────────┘
```

We'll make this decision when we build the task interface.

Mobile:


# 7.11 Navigation Strategy

### Desktop

```text
Persistent sidebar
```

### Tablet

```text
Compact sidebar
```

### Mobile

```text
Header
  ↓
Menu trigger
  ↓
Navigation drawer/menu
```

The navigation should remain available without consuming most of the mobile screen.

---

# 7.12 Responsive Spacing

We won't use identical spacing everywhere.

Conceptually:

```text
Desktop
More breathing room

Tablet
Moderate spacing

Mobile
Compact but comfortable
```

For example, a large desktop section might use:

```text
32–40px
```

while mobile might use:

```text
20–24px
```

The goal isn't "make everything smaller."

It's:

> **Use the available space intelligently.**

---

# 7.13 Responsive Typography

We can slightly reduce large headings on smaller screens.

For example:

```text
Desktop
32px

Tablet
28–30px

Mobile
24–28px
```

But body text shouldn't become tiny just to fit more content.

Readability comes first.

---

# 7.14 Responsive Engineering Rule

Here's the rule I want you to remember while building DevFlow:

> **Responsive design is not a collection of media-query fixes. It is designing how the interface changes as the available space changes.**

We'll use Tailwind's responsive utilities to implement this.

You'll therefore learn Tailwind through actual problems such as:

```text
"These three cards need to become one column on mobile."

→ Think about layout.

→ Decide breakpoint.

→ Implement responsive utilities.

→ Test.

→ Inspect.

→ Adjust.
```

That's exactly the kind of practical Tailwind learning we want.
